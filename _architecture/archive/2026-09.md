## 2026-09-01 — TypeORM/sqlite3 replaced with raw node:sqlite

Implemented `_architecture/plans/2026-09-01-nx-removal-and-storage-backend-rethink.md`'s Decision 2, ahead of Decision 1 (Nx removal), per plan `fancy-sauteeing-puzzle.md` (reviewed by an Opus subagent before approval). `api/src/app/notes.service.ts` rewritten off raw `node:sqlite` (`DatabaseSync`) instead of TypeORM; new `api/src/app/database.provider.ts` holds the `SqliteDb` provider + `withTransaction` helper; `document.entity.ts`/`folder.entity.ts` deleted; `app.module.ts` and `main.ts` (added `enableShutdownHooks()`) updated; `notes.service.spec.ts` rewritten to pass real `userId` args and run against a temp-file DB (previously didn't compile). `typeorm`, `@nestjs/typeorm`, `sqlite3` removed from `package.json`; `@types/node` bumped `20.19.9` → `^24`; added `engines.node: ">=23.4"`.

One deviation from the plan found during implementation: the `SqliteDb` class's constructor took an optional `databasePath` param for test injection, which made Nest's DI try to resolve it as a dependency and crash on boot (`UnknownDependenciesException`). Fixed with `@Optional()` on the param — not in the original plan, straightforward once seen.

Verified: `notes.service.spec.ts` newly passes (3/3). `nx serve api` boots clean against the real `data/notes.sqlite` — DDL is a true no-op on the existing tables/indices. Manual smoke test via curl (login, create/rename/move folder+doc, delete folder cascade, delete doc) against a throwaway `userId` confirmed `updatedAt` bumps correctly and stays UTC-correct end to end; real user data (`jokoivi`, `annaka`) untouched. `npm ls typeorm sqlite3 @nestjs/typeorm` empty, `@types/node` at `^24`. Backup `data/notes.sqlite.bak-pre-node-sqlite` kept as a safety copy, not yet deleted.

Nx removal (Decision 1) still entirely unstarted.

## 2026-09-02 — Nx removed, npm workspaces + direct CLI tooling in place

Implemented Decision 1 of `plans/2026-09-01-nx-removal-and-storage-backend-rethink.md`, per plan `fancy-sauteeing-puzzle.md` (reviewed by an Opus subagent, 9 findings folded in before approval). Staged as three independently-revertable steps: (1) split root `package.json` into `web/package.json` + `api/package.json` under `"workspaces"`, Nx still driving builds — verified unchanged; (2) added the new tooling (`angular.json` at repo root, `api/nest-cli.json`, standalone `api/jest.config.cts`, rewritten eslint configs) alongside Nx, verified each independently; (3) deleted `nx.json`, `.nx/`, `web/project.json`, `api/project.json`, `api/webpack.config.js`, root `jest.config.ts`/`jest.preset.js`, stripped all `@nx/*`/`nx`/`@swc*`/`@oxc-project/runtime`/`ts-node`/`webpack-cli` from root `package.json`, rewrote root scripts to npm-workspace-native versions, added `concurrently` for `watch`.

Two fixes found only by building, not in the original plan draft: `api/tsconfig.app.json`'s `outDir` was `../dist/out-tsc` (dead Nx-era path) — fixed to `../dist/api`. And the final `npm install` (which prunes anything no package.json references) silently dropped `dotenv` and `@types/express` — they'd been root-level deps with no explicit owner after the split; `nest build` failing on missing types caught it. Added both to `api/package.json`.

Verified: `npm run build` (web + api) clean; `npm run start:api` boots against real `data/notes.sqlite`, correct 401 on protected route; `npm run test` — web vitest 1/1, api jest 3/3 (including the 5 specs importing `@shared/models` via the new `moduleNameMapper`); `npm run lint` — same pre-existing error count as before the migration (all in `backups/v1`'s bundled JS and `build-web.js`'s Node globals, unrelated to this change, not new); `npm ls` confirms every Nx/swc/oxc package gone (759 packages dropped from `node_modules` on the final install); `node build-web.js` end-to-end with the new `ng build` invocation.
